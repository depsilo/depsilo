# Depsilo 小规模试用指南

本指南用于维护者安排隔离试用。建议目标是 10 个独立实例，其中至少 5
个连续使用两周并经历一次升级或恢复；这些是观察计划，不是已经发生的
客户数据或发布证据。

## 安装与首次接入

二进制安装：

```bash
curl -fsSL https://depsilo.com/install.sh | bash
depsilo serve
```

或使用容器：

```bash
docker run -d --name depsilo -p 23333:23333 \
  -v depsilo-data:/root/.depsilo --restart unless-stopped \
  ghcr.io/depsilo/depsilo:X.Y.Z
```

打开 `http://127.0.0.1:23333` 完成首次管理员设置。在一个 Python 或
Node 项目中，把包管理器的 registry/index 指向 Portal 提供的连接地址，
安装一个锁定版本的依赖，然后重复安装一次，确认第二次请求显示缓存复用。
不要在试用中使用私有包、生产凭据或未锁定的大型依赖树。

## 安全故障与恢复演练

在专用测试项目中暂时停止上游或将测试用 Upstream 指向不可达地址，记录
一次请求失败和 Admin 中的上游故障状态。恢复上游后重试同一个锁定版本，
确认成功结果与先前失败区分显示。演练结束后恢复原配置；不要对生产上游
执行破坏性操作。

导出备份到试用目录，停止服务，复制或隔离状态目录后再恢复备份，重新启动
并验证管理员登录、规则和已缓存的测试依赖。缓存对象是否包含在备份中以
部署文档的说明为准，不能把备份当作缓存对象归档。

## 反馈字段

- 实例系统、安装方式、Depsilo 版本和候选 commit
- 使用的 Python/Node 项目规模（仅写公开依赖数量）
- 首次安装和重复安装的体感耗时、命中/未命中结果
- 上游故障演练的时间、请求路径和恢复结果
- 升级或恢复是否保留登录、规则和配置
- 最困惑的界面文案、缺失的状态或下一步
- 是否愿意继续使用，以及需要的支持

如需提交诊断包，在本地执行：

```bash
depsilo diagnose --out depsilo-diagnostic.json
```

提交前检查文件内容，删除主机名、路径和任何私有信息；不要粘贴
`config.toml`、Token、密码或私有包列表。诊断包只用于维护者明确同意的
问题单，不能替代日志和复现步骤。
