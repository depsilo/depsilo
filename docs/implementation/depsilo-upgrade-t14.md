# T14 清理执行绑定与并发安全

- 清理预览响应现在带短期 `plan_id`（5 分钟）；计划只保存在进程内，最多
  32 个，服务重启后自然失效，不新增数据库迁移或任务队列。
- 计划绑定创建它的操作者。执行前重新检查写权限、计划有效期和所有候选
  的 key、大小、生态、包名、TTL、最后访问时间；对象已消失或元数据改变
  时计为 `skipped`，删除错误计为 `failed`。
- `Retention.RemoveIfMatches` 仍通过既有每 key mutation gate 和对象先于
  元数据删除顺序，活跃写入/流式请求不会绕过 cache owner。重复提交同一
  计划不会扩大删除范围，计划取出后即失效。
- 缺少 `plan_id` 的旧 API 调用暂时保留原有宽泛清理语义；Admin 清理弹窗
  始终使用绑定计划，并在没有预览时禁用确认按钮。

已通过 Retention、Admin API、前端类型和单元检查；完整 `make check` 在
提交前复验。跨用户、过期计划和元数据更新的行为由服务端 fail-closed，
后续可在 T14 专项测试中继续扩展审计结果展示。
