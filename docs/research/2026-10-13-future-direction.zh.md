# 未来方向：当前现状（2026-10-13）

> [ADR-0005](../adr/0005-enforcement-first-until-1-0.md) 为准。

## 已交付与开发中

- 当前检出的最新标签是 `v0.11.0`：已交付不同可信程度的最小发布年龄门控、
  ADR-0005 指定的八个生态的恶意包数据、只读快照模式和 CRA 模式 SBOM 导出。
  产品支持 14 条标准包路径及单独的 Docker OCI 路径，而非 15 个标准生态。
  参见 [PRODUCT.md](../../PRODUCT.md)、[生态目录](../../internal/ecosystem/catalog.go)
  和 [CHANGELOG.md](../../CHANGELOG.md)。
- 当前 `master` 还包含未发布的级联缓存及 Admin 改动（见 CHANGELOG 的
  `Unreleased`），以及进程内 macOS/Linux 托盘入口与发布构建任务。托盘在
  浏览器中打开 Web UI，不是重新设计的原生桌面窗口，也没有 Windows 安装器。
  构建任务存在不代表桌面版本已经发布。

## 1.0 准备程度

对照 [ADR-0005 第 5 节](../adr/0005-enforcement-first-until-1-0.md)**原文的六项退出标准**：

| 标准 | 仓库现状 |
| --- | --- |
| 1. 发布时间来源绑定 | 在启用的路径上已实现；部分生态明确使用近似时间或首次观察时间。Composer 客户端可在 451 后回退到上游 dist URL，因此仍属 best-effort。 |
| 2. 恶意包数据 | **指定的八个生态均已覆盖**。名单之外的生态没有同等覆盖，这是已记录的限制，**不是**该标准额外要求的 1.0 阻塞项。 |
| 3. 冻结/快照 MVP | 已随 `v0.11.0` 交付；导出清单不包含制品字节。 |
| 4. CRA 模式 SBOM | 按 ADR 要求的字段、签名与预设实现；输出 SPDX 2.3 或 CycloneDX 1.5，不代表法律意义上的合规。 |
| 5. 候选版发布证据 | **未完成**。检查工具和发布自动化已经存在，但当前仓库没有 `v1.0.0` 候选版的签名制品、S3、升级/回滚和真实客户端验证记录。 |
| 6. 兼容性政策 | 已发布并明确弃用窗口。[现行列表](../compatibility.md#current-deprecations)已说明 `q`、`search` 旧别名仍有效且尚未宣布 Sunset；正式宣布移除前仍需验证运行时弃用提示。 |

因此，未取得第 5 项的候选版证据并复核剩余契约问题前，不能宣称 1.0
已通过资格验证。旧研究的“六项中五项已满足、只差一次测试”与自身表格矛盾；
把名单外生态算作第 2 项阻塞因素，也误读了 ADR。

## 接下来的判断

1. **1.0 前：**检查实际客户端路径及提供制品的上游上的发布时间语义。
   Composer 目前使用 `time`，CRAN 使用 DESCRIPTION 的 `Date/Publication`
   或 Last-Modified；npm 的年龄判断需要完整发布时间表。对照当前上游
   元数据核验，明确标注 best-effort/近似行为，再按
   [发布清单](../../RELEASE_CHECKLIST.md)留存候选版完整验证证据。
2. **1.0 后，需另行决策：**评估可用于拦截的上游发布者证明、VEX/SBOM
   互通和面向运维的共存指南。这些是提案，不是已交付功能或确定排期。
   “来源绑定”的时间戳并不等于发布者的密码学证明。
3. **仅在有用户证据及新 ADR 时：**重新评估通用制品仓库。当前仍维持
   SQLite 加本地/S3 存储的单实例部署，以及既定生态范围。

**法规边界：**根据[欧盟委员会的报告义务说明](https://digital-strategy.ec.europa.eu/en/policies/cra-reporting)，
CRA 对制造商的报告义务于 2026-09-11 开始，对开源软件管理者则于
2027-12-11 开始。仅凭“代理第三方包”或 MIT 许可，不能判定 Depsilo
自身产品的适用性；在单独完成法律评估前，不应宣称合规或豁免。
