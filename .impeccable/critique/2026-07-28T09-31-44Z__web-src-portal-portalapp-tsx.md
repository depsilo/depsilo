## 设计独特性判断

### LLM 评估

门户确实是为 Depsilo 创作的，不是可替换品牌的通用模板。实时端点、可审查 AI 提示词、生态配置控制台、语义化健康状态、上游延迟 beats 都有明确的依赖基础设施特征。

问题是两种人格没有完全统一：Monitor 是成熟、克制的运维工具；Quick Start 更像开发者 SaaS 的宣传首屏。大标题、带动效的复制 CTA、编译缓存推广和第二套 AI 提示词，共同抢走了“完成第一个包管理器接入”应有的主导地位。这与 DESIGN.md 中“Portal 不是营销落地页”的约束冲突。

### 确定性检测

源码 CLI 检测 `web/src/portal` 返回 **0 项**。浏览器运行态检测则发现：

- Quick Start 桌面：18 个元素组、20 条规则命中。
- Quick Start 手机：12 个元素组、14 条规则命中。
- Monitor 桌面：15 个元素组、16 条规则命中。
- Monitor 手机：13 个元素组、14 条规则命中。

真实问题主要是：

- 10px 功能文字和多处 11–11.5px 辅助文字；
- 深色模式中数处 `4.4:1` 的临界低对比度；
- 编译缓存说明行宽过长；
- Monitor 卡片状态与历史摘要字号过小；
- 嵌套的提示词/代码表面增加视觉层级。

明确的误报包括：只在 Admin 使用的宽度 transition 与下载流动画、Quick Start 复合分栏被判作缺少 padding，以及 DESIGN.md 已明确允许的绿色品牌光晕。嵌套卡片则属于情境性提醒：代码终端有功能理由，但仍会增加首屏视觉噪声。

### 视觉覆盖层

运行态脚本成功注入四个独立浏览器视图，所有检测覆盖层都在 DOM 中可见并被截图验证。由于当前环境没有原生可见浏览器能力，使用的是无头 Playwright，因此没有可留给用户查看的 `[Human]` 标签页；可靠替代证据为截图、DOM 覆盖层计数和 `detect.js` 控制台信息。

## 总体印象

Monitor 已经接近可发布质量；Quick Start 的最大机会不是再加装饰，而是重新定义任务顺序。现在的门户先展示“产品能做很多”，然后才帮助用户“把第一个依赖请求接进来”。对个人开发者和小公司，这会放大维护成本感。

## 做得好的地方

1. **产品专属的仪表感。** 真实 Origin、生态图标、管理器命令、延迟 beats 和健康阈值让界面可信，不像静态演示。
2. **Monitor 状态设计完整。** 初始加载、首次失败、缓存数据刷新失败、历史失败、成功空状态和搜索空状态被清晰区分。
3. **视觉系统已经成形。** Inter Tight / Inter / JetBrains Mono、克制表面、绿色/琥珀/红色语义、明暗主题和 reduced-motion 形成稳定的 Instrument 语言。

## 认知负担

Quick Start 为高负担，8 项检查中约 6 项失败：

- AI 项目接入、编译缓存、生态选择和管理器选择同时竞争。
- 14 个生态以及 Python 下 AI + 7 个管理器超过工作记忆容量。
- 两套 AI 提示词要求用户记住并推断作用域。
- 专业编译缓存说明在第一次成功之前全部展开。
- 核心包管理器接入不是视觉上最强的任务。

Monitor 为低负担，搜索、全局摘要、分组卡片和文字化状态可以快速扫描。

## 情绪旅程

Quick Start 以“装得快，也装得放心”建立信心，随后进入情绪低谷：新用户依次看到供应链术语、专业编译缓存、14 个生态和第二条 AI 路径，却还没有完成一次安装。当前高点是“复制成功”，结束却不是“Depsilo 已观察到你的第一个缓存请求”，峰终体验不完整。

Monitor 的旅程更好：用户先得到“服务是否正常”的答案，再按生态检查上游；错误恢复平静且可执行。弱点是移动端隐藏全局在线状态，空状态也缺少前往配置的下一步。

## 优先问题

### [P1] 支持的手机宽度下，顶部 Admin 入口被裁切

**为什么重要：** 390px 时按钮右边界约为 408.7px；375px 和 320px 也会越界。页面本身不产生横向滚动，因此用户甚至无法滚动找到完整入口。

**修复：** 在约 420px 以下进一步折叠低优先级控件或隐藏文字 Logo；为顶栏加入 320/375/390px 的每个控件边界断言。

**建议命令：** `$impeccable adapt`

### [P1] 首次接入主任务被两个次要模块推到页面深处

**为什么重要：** 页面顺序是 AI Hero → 编译缓存 → 配置控制台。390px 下控制台约从 y=1295 开始，配置内容还要经过 280px 的生态列表；个人开发者很难在一分钟内完成第一次接入。

**修复：** 主线改成“选择生态 → 选择推荐管理器 → 复制配置 → 验证请求”；项目级 AI 作为这条路径中的可选加速器，编译缓存放到首次成功之后。

**建议命令：** `$impeccable onboard`

### [P1] 两套 AI 接入体验形成没有解释的分叉

**为什么重要：** Hero 的项目级提示词和 ConfigurePane 默认的生态级“自动配置”都要求粘贴到 Claude/Cursor，但没有说明作用域、差异和推荐场景。

**修复：** 明确区分“配置当前项目”“配置当前机器/包管理器”“配置编译缓存”，只保留一条推荐路径，并合并重复提示词表面。

**建议命令：** `$impeccable clarify`

### [P2] 选择密度和布局比例削弱配置控制台

**为什么重要：** 14 个生态和最多 8 个管理器同时可见；手机上变成嵌套滚动，桌面上高目录又把右侧撑出大量空白。

**修复：** 增加搜索/最近使用，管理器只展示推荐项并把其余放入“更多”；采用内容驱动高度或粘性紧凑目录。

**建议命令：** `$impeccable distill`

### [P2] 微控件与辅助文字尚未达到完整的无障碍和触控质量

**为什么重要：** 存在多处 10–11.5px 文本、4.4:1 对比度、16×16 搜索清空按钮、无朗读反馈的端点复制，以及仅 hover 可查看的延迟历史。触控、低视力和屏幕阅读器用户会直接损失信息或反馈。

**修复：** 统一共享控件，功能触控目标至少 40–44px；复制状态使用 `aria-live`；本地化 Copy；延迟详情支持 focus/tap；修正字号与对比度。

**建议命令：** `$impeccable audit`

## Persona 风险

**Jordan（第一次使用）：** 无法判断应复制顶部提示词还是先选择生态；“最小发布年龄”“窄 WebDAV”“不交叉命中”等术语在基础成功前出现，容易在控制台之前放弃。

**Casey（分心的手机用户）：** Admin 被裁切，配置入口接近两个屏幕后，生态目录又形成嵌套滚动；延迟历史没有触控入口。

**Riley（压力测试者）：** Monitor 的错误/空状态很好，但剪贴板失败静默、顶栏 stats 失败会直接移除状态与版本，超长搜索词会原样进入空状态标题。

**Morgan（个人开发者/小公司技术负责人）：** 目标是尽快让第一个包通过代理；当前两个 AI 路径和提前出现的编译缓存说明，反而让产品显得比预期更难维护。

## 次要观察

- 浏览器标题仍是通用的 `web`，不利于标签页识别。
- “Configure Python” 使用 `<span>` 而非标题，核心任务没有进入页面标题层级。
- Monitor 的 230px 搜索框会截断英文占位文字。
- 手机隐藏主题和全局服务状态。
- Monitor 空状态应为有权限的 Operator 提供上游配置入口。
- 重复的生态 SVG 可访问名称可能与旁边的可见文字产生冗余朗读。
